## ชุดข้อมูลย้อนหลัง 5 ปีและข้อจำกัดที่ยังเหลือ

ใช้ fixture เดิม **100 ผู้ใช้ × 3 เครื่อง × 1,826 วัน** ไม่ใช่ผลรับรอง 200 ผู้ใช้ มี Subject 547,800 แถว, Raw 547,800 แถว, Meter/Ledger อย่างละ 5,478 แถว Raw เป็น Total หนึ่งตัวต่อผู้ใช้ ไม่ใช่ทุก counter ทุกครั้งที่อ่าน

|---|---:|---:|

| Settings ครั้งแรก | 4.64 | 1.63 |
| Users เดือนล่าสุด | 5.89 | 2.75 |
| Printers เดือนล่าสุด | 1.42 | 0.68 |
| Usage เดือนล่าสุด | 0.49 | 0.44 |

| Users เลือกช่วงเต็ม 5 ปี | ไม่พร้อมหลัง 180 วินาที | **83.30** |

หลังแก้ครบ ชุดวัดจบโดยไม่มี report error และ Users snapshot มี Raw ครบ 547,800 แถว, Subject ที่รวมแล้ว 300 กลุ่ม, daily/category costs 5,478 รายการ ส่วน Users/Legacy ใช้ Raw tuple ร่วมกันหนึ่งชุด

**ยังไม่ถือว่า Users ช่วงเต็ม 5 ปีเร็วพอ:** อ่านและสร้าง Subject ใช้ 31.35 วินาที, Raw 42.70 วินาที และสร้าง user model 5.06 วินาที ค่าราคาที่เคยอ่านทีละวันลดเหลือ 0.27 วินาที ข้อมูลจำนวนมากยังต้องแปลงเป็น Python records ก่อนรวมเป็นตาราง; การแก้ขั้นถัดไปควรใช้ผลรวมที่เตรียมไว้และโหลดรายละเอียดเฉพาะส่วน โดยต้องรักษากฎฉบับแก้ไขและราคาเดิม

ช่วงที่ event loop ไม่ได้รับ callback ยาวที่สุดของ Users ช่วง 5 ปียัง 1.62 วินาที และ peak working set ของ process ทั้งชุดประมาณ 837 MiB จึงไม่ใช้ผลทดสอบเดือนเดียวรับรองความลื่นหรือหน่วยความจำของรายงานทั้ง 5 ปี
