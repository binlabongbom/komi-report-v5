# KOMI Report 5.2.11 candidate

This is an unapproved candidate, not a Production GO. Main is unchanged.

- Numeric settings editors (prices, percentages, billing day, ports and polling intervals) explicitly use ASCII digits 0-9 and a dot decimal separator, independent of Windows/parent locale. Thai labels and suffixes remain supported. Regression coverage exercises display, keyboard entry, stepping and reparenting under th_TH, ar_EG, fa_IR and de_DE. Verification on an affected customer's installed Windows environment is still required.
- Date/calendar and schedule-time editors use the same explicit locale. Desktop and Setup Lab initialize a stable Qt locale for other widgets, table delegates and progress labels. Web count, money and date formatters explicitly request Latin digits while preserving the existing Thai/English date calendar conventions. Generated numeric report strings and Excel numeric cells retain their existing values and formatting.
- Desktop page navigation now uses a shared left-aligned tab style and heading for Settings and Reports. Settings has General, Automation, Status/history and Advanced; the existing automation plan lives beside its schedule editor. Schedule shortcuts open and scroll to the editor directly. Forms remain open after Save/Cancel, and unsaved edits block a tab change. Weekday controls use two rows to avoid squeezed labels on small windows.
- Window, dialog and tray icons use the existing multi-resolution Logo.ico. Installer shortcut AppUserModelID now matches the running process. Sidebar logo rendering preserves device-pixel resolution on scaled screens. No change to the installer AppId or user-data paths.
- Windows UI/branding verification (2026-09-17): 81 related tests passed, plus 8 numeric locale subtests. The earlier 870px report-width failure was reproduced on HEAD and traced to an offscreen Qt environment with zero available fonts; the QA fixture now loads Windows fonts and uses the app's actual default font, and that test passes. Settings captures were inspected at 1024, 1280 and 1440px in Thai/English. Web `test:numeric`: 2 passed; TypeScript check passed. Installer rebuild, live Windows taskbar/upgrade validation and affected-machine validation: NOT RUN.

- Normal: Online Registration, redacted transport diagnostics and late-result handling.
- Offline: no Registration/Status/Meter transport; a Host-signed Offline License remains required. No private/master key is bundled. Missing public verification keys are a delivery blocker, never a reason to bypass activation.
- Primary: persistent Peer Sync default after setup/startup, including one-time legacy migration. Explicit Off in this version survives restarts. Legacy Off was represented by an absent file and cannot be distinguished from never-configured; upgrading therefore applies the requested new default once.
- The LAN service is available while Desktop/tray is running, not after Exit, sleep or power-off. Existing explicit Web-service disable is respected.
- Windows Web shortcuts now target the available Python runtime and `app.py --open-web`, including installed layouts without the source CMD files. The existing Desktop receives the Web-open command over its local instance channel, owns the service, and opens the LAN IP/custom port when ready. Installer shortcuts repair existing broken Web links on upgrade.
- Read-only Web reports open without a password by default. Previously unconfigured installs migrate to that default; existing owner-configured locks remain. Desktop LAN settings has an opt-in password lock and requires setting a code before reports can be locked. Privileged endpoints and writes stay outside the anonymous allow-list. HTTPS remains enabled.
- Source Web startup now imports its package correctly, queries parent-process liveness without Windows `os.kill(pid, 0)`, and uses a stop request so the worker can close its API/Node children before restart. On 2026-09-17 the user authorized stopping the installed 5.2.10 process and launching the latest source: the 5.2.11 window and its existing data were confirmed through Windows accessibility, and Web started successfully after preparing its runtime. Certificate-validated requests to the LAN address returned 200 for reports and anonymous session status, with `reportPasswordless: true`; protected settings returned 401. Browser navigation remains blocked by `ERR_CERT_AUTHORITY_INVALID` for the generated certificate. No browser warning was bypassed or OS trust store changed; installer upgrade and graceful Web restart UAT remain pending.
- Always-open claims are not device authentication. Use a trusted LAN, scope the OS firewall to approved subnets/profiles, never expose the service to the Internet. Secrets/history are excluded from setup snapshots.
- Both installers share the existing per-user AppId/data path: alternatives for in-place install, not side-by-side editions. Back up before switching edition; switching to Offline requires offline activation.

Required validation: native Windows tests; fresh install and 5.2.10 upgrade; second-machine handoff; no Internet with LAN retained; license import/mismatch/expiry; no credentials in diagnostics; final installer SHA256 and signature evidence. No automatic publish or installation onto the runner's real user data.
